## 01 · Commit-quiz · 提交代码前，先考考提交者

**做什么：** 一个 Git pre-commit hook：在提交 AI 生成的改动前，要求开发者回答关于本次 diff 的问题。

**具体做法：** 调用已有 AI CLI，把 staged diff 变成四个陈述，其中两个正确、两个貌似合理但错误。答错会中止提交并展示真实改动摘要；模型或交互不可用时放行。

**材料边界：** 已读 README，未安装试用。尚不清楚题目能否测出理解程度，以及长期使用是否变成机械答题。

## 02 · Lossy Git · 把代码提交进神经网络

**做什么：** 一个浏览器实验：commit 时训练小神经网络记住文件，checkout 时从权重重建，文件可能被记错。

**具体做法：** 用位置编码映射代码字节或图像像素；可以调网络大小和训练次数，对照原文件与重建结果，观察压缩与错误之间的关系。

**材料边界：** 已读演示页说明，未运行页面里的代码。它明确定位为实验，不能当可靠版本控制系统。

## 05 · Melra · 写操作结果不明时，先停下来核对

**做什么：** 一个供 agent 调用的本地执行层，统一检查工具权限、验证执行证据，并记录操作回执。

**具体做法：** 对经过它的任务写操作，在派发前记录状态并限制最多派发一次；超时或崩溃后若无法确认结果，就进入待核对状态，不盲目重放。文档明确外部效果的 exactly-once 仍依赖服务方。

**材料边界：** 已读 README，未做故障注入。只约束经由该运行时的调用；存储状态和核对逻辑的可靠性尚未验证。

## 06 · ANE Fieldfare · 用 ANE、GPU 和文件缓存协作推理

**做什么：** 在 Apple Silicon 上运行稀疏专家模型的实验实现，试图降低预填充延迟并提高生成速度。

**具体做法：** README 描述 GPU 解包量化专家、ANE 进行部分预填充计算，生成时在 GPU 上做推测解码，并通过 mmap 让操作系统文件缓存承载专家权重。

**材料边界：** 作者给出分工作负载的测量，未独立复现。标题的峰值速度不是普遍速度；较小的进程 RSS 不代表操作系统缓存不占内存。使用私有 Apple 接口。

**来源：** [项目 / README](https://github.com/zw5/ane-fieldfare) · [HN 原帖与作者说明](https://news.ycombinator.com/item?id=50174998)
