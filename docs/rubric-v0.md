# 判断标准 v0 · 待用户校准

目标：发现被忽略、值得用户阅读的 Show HN 工作。原创性和个人兴趣分别记录；热度只决定候选资格，不替代质量判断。

## 判断链

1. **材料是否足够？** 能否说明项目做什么、如何做，有可引用的实现或演示说明？无法读取网页、只有口号、视频未查看时允许 `unsure`。缺少材料不等于不原创。
2. **具体差异在哪里？** 指出相对常见做法改变的约束、机制、交互或对象。小众领域、开源、技术堆栈新、工程量大本身不算差异。
3. **有何可迁移的 insight？** 是否揭示了忽略的需求、反直觉的简化、重要取舍，或把已有元素组合为新的体验？合理组合也可能有价值；不预设 AI wrapper 一律无趣。
4. **证据支撑到哪？** 分开作者主张、可读实现说明、独立验证。模型不熟悉不等于世界首次。指出最接近的已知方案；未做搜索时标明未核实。
5. **值得打断用户吗？** 给出 `push / pass / unsure` 和一句具体理由。允许有原创性但不符合用户兴趣，允许零推荐。

## 暂不纳入质量分

- 票数、GitHub stars、榜单排名：用于候选资格与观察，不用来评判 originality。
- 营收、商业规模、UI 精致程度、代码行数：不是用户当前提出的目标。
- 是否用了 AI、是否开源：记录事实，不自动加减分。
- 页面无法抓取：记录采集问题，不视为项目质量差。

## 用户反馈

- `decision`: push（值得推）、pass（不值得推）、unsure（信息不足/无法判断）。
- `originality`: yes / no / unclear；`interest`: yes / no / unclear。可选；未回答时保留 unclear。
- `reason`: 用户原话；不要由助手补写为用户观点。
- 全部修改追加记录，不覆盖历史。助手初评始终与人类标签分开。

## 首轮样本与指标

本轮 30 个真实案例是偏好探索集，不是最终测试集。随机样本与刻意挑选的边界案例分别记录采样来源；正式指标需按来源分组，不能把富集的正例比例当作真实流量的准确率。

标签收齐后优先比较：推送 precision、人工标注样本内的 recall、unsure 比例和覆盖率；precision 的分母为实际推送数，零推送时记为未定义，不记为 100%。对未标注条目不推断正负。K 是每日上限，不是配额。

生产漏检率需要额外随机抽查被拒绝项目。30 个开发案例只适合发现大分歧，不能支持“提高几个百分点”的结论。冻结标准后再采集后续日期的新帖作为独立测试，按项目去重，防止同一项目更新跨集合泄漏。

## 未上榜的记录方式

- `/show` 含分页；保存每一页和抓取起止时间。不是原子快照，不能保证捕捉两次轮询之间的短暂上榜。
- 任一页失败、解析为空、分页循环或达到上限：覆盖不足，缺席状态只能是 unknown。
- 记录当前 present/absent/unknown 和历史 observed_ever_show。首次采集前一律 unknown。
- 真正上线时需设定观察时长（暂定 24 小时）、允许的采样间隔和发布前重查。当前工具只采集快照，未实现持续观察资格与自动发布。
