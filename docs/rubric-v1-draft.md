## 二、评测怎么打分

### 决定(程序打分,对照她的标签)

- 主指标 `agree`:agent 的 `push / pass` 与她的标签一致的比例。`unsure` 一律算不一致,不会被悄悄当作正确。恒定答案的基线是 50%。
- 辅助:precision(分母是实际推送数,零推送则未定义)、recall、specificity、unsure 率、格式有效率。
- 按抽样来源分组:`random` 近似真实流量,`purposeful` 是刻意挑选的边界案例,两组分开报。
- 30 个案例 × 3 次重复,噪声大约 ±10 个百分点,低于这个差别不当作改进。

### 理由(judge 打分,只看理由,不看决定)

| 项 | 判真的条件 | 判假的条件 |
|---|---|---|
| `grounded` | 理由里关于项目、页面、作者、评论的每条事实都能在证据里找到。 | 有编造、矛盾,或说“首个”“已测试”而证据没显示。 |
| `specific` | 点名了这篇帖子里的具体功能、机制、约束或目标用户。 | 放到任何帖子都成立(“有意思”“拥挤的赛道”)。 |
| `consistent` | 理由支持所给的决定。 | 理由支持相反决定,或 `unsure` 没说缺什么。 |

v1 草案拟加一项 `uses_criteria`:理由指出了 P1–P5 或 X1–X7 里的哪一条依据。这一项还没进 judge,也没经过校准,先不计入。

### 试点里的实际打分示例(baseline,claude-haiku-5-5)

| 案例 | 她的标签 | agent | agree | grounded / specific / consistent | 为什么 |
|---|---|---|---|---|---|
| 03 Moodly | push | pass | 0 | 1 / 1 / 1 | 理由写“常见做法,没有新机制”,事实无误,但用的是 v0 的技术差异标准,不是 P1。 |
| 26 Context Window | push | pass | 0 | 1 / 1 / 1 | 理由说“网页变更检测本身是常见做法”,恰好是她明说不影响推送的点。 |
| 20 Pope Pendle Pro | pass | unsure | 0 | 1 / 1 / 1 | 页面 404,v0 允许 `unsure`;她判 pass(X3)。理由本身合格,扣分来自决定。 |

三条理由本身质量都不错,但决定都和她不一致。这说明理由评分和决定评分衡量的是两件事:决定错的原因,基本在用的标准不对,而不是理由写得差。
